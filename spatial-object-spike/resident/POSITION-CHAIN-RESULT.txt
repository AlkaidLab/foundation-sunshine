POSITION CHAIN RESULT / 2026-10-17
=================================

Conclusion
----------
The locally installed Nioh 3 DOES supply nonzero, changing spatial positions on
the tested Dolby Atmos for Home Theater route. Real captured dynamic mono audio
can be matched to those positions in audiodg, without a virtual driver, per-game
injection or live breakpoints. The previous all-zero-XYZ interpretation was
incomplete; it is NOT evidence that this game lacks object support.

Root cause
----------
The private basic properties are INCREMENTAL UPDATES, not complete current-state
snapshots. Matching audioeng disassembly gates creation with flag 0x1, volume with
0x2, position with 0x4, end with 0x8, extended properties with 0x10. Most packets
in quiet periods are volume-only (0x2) and contain zero-filled XYZ. Those XYZ are
not new positions. A late-attached collector can also miss initial coordinates.
The decoder must retain observed XYZ, apply new XYZ only when 0x4 is set, and
mark unknown initial state. We corrected the diagnostic decoder and tested this.
The default Dolby collector now includes flags, incremental state, explicit unknown
positions and generation/loss handling. See README.txt and STATEFUL-RESULT.txt for
the subsequent mid-attachment, soak and file-rotation checks. --backend metadata
remains available only when the full paired diagnostic trace is needed.

Support scope
-------------
This verifies the installed PC build/configuration. XYZ are listener-relative
engine coordinates, not game-world coordinates or named character/entity IDs.
Local imports/modules include XAudio2_9.dll, but that alone cannot determine native
object support. The actual positive trace is stronger evidence than import names
or PS5 marketing. PS5's official page lists 3D audio; the inspected PC pages did
not document this exact API, so PS5 support was NOT used as proof for this PC result.
