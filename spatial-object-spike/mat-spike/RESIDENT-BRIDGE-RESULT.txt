本轮结论
--------
无需游戏、无需UAC，已经把既有《仁王3》原始采集记录接入一个可验证的离线桥接原型：
读取分卷 -> 重放坐标/音量增量缓存 -> 稳定对象身份 -> F32增益归一 -> 480帧对象输入 -> 有界队列。
不是重新生成两个固定对象的音频，也不是只读旧input.npz；直接从完整disk-v2记录重建。

最终 bridge-replay03/ 和 bridge-proof01/ 通过：
  - 全部73186条记录、35129280个对象样本均有明确归类；原始36个分卷未修改。
  - 1978轮480帧，音频时钟19.78秒，跨35次分卷切换；坐标/音量缓存与采集时快照一致。
  - 8个恢复坐标的动态对象输出2354400样本；未知坐标期间的34655条记录全部是零PCM，
    明确延后建立对象，不伪造原点。17路静态床的16140480样本单独完整保留。
  - 处理后的PCM、XYZ、源对象映射/通知，与另一遍直接使用原采集快照的golden逐字节一致。
  - 最后6秒按原始QPC到达节奏做600轮有界队列回放，无溢出/10ms截止超时，输出与不限速回放一致。

没有调用audiodg或任何Dolby组件，没有开游戏或新增DLL驻留；没有产生MAT码流。
输出是自定义“待编码输入”诊断文件，不是Dolby MAT、IEC61937、WAV或可直接播放的媒体。
还不能报告真实游戏全链路MAT编码通过，尤其不能丢掉静态床后声称完整游戏音频已完成。

重要发现：不能依赖回调列表位置
----------------------------
第一次严格回放在轮376（名义3.76秒）停止：37个对象集合没变，但回调顺序变了。
总计1362轮的排列不同于最初一轮，不等于发生1362次排序变化。
若把数组下标当对象身份，接入真实游戏后会错绑PCM/坐标，这是合成固定列表没有覆盖的风险。

现已改成：
  source slot按(host,objectId,type)稳定分配，不随当轮排列变动。
  编码身份按(session,host,objectId,type,lossEpoch,generation)隔离。
  Native ID在本会话单调分配；新代次结束旧ID，不复用旧Native ID，避免残留缓存串入。
  原始顺序保留用于到达QPC/审计，不重写源文件。
  坐标只在flags&4时取rawXYZ更新；flags&2等增量沿用缓存，unknown保持None/NaN。
  只有真正source create且未显式给位置时，才采用协议定义的默认原点。

重要限制：旧采集缺少可信的音频更新轮次字段
----------------------------------------
disk-v2只有回调到达QPC/序号，没有原生render quantum ID、sample frame start或对象内偏移。
本录制每一轮刚好完整覆盖相同37个key，各480帧；严格检查集合完整、每key恰好一次，
允许轮内顺序变化。第一轮到最后一轮全都满足；残缺/重复/非480帧输入会拒绝。
这属于“此录制专用的已核对重建条件”，不是通用实时轮次检测算法。

源一轮内部QPC跨度：中位0.0185ms，最大0.1768ms。
相邻轮开始QPC间隔：中位10.0008ms，最小9.7645ms，最大10.2433ms。
这些支持本次批次分组，但不是系统提供的呈现时间戳或可泛化的同步保证。
不能把QPC四舍五入成10ms音频网格，或据QPC抖动补静音、丢样本、重采样。
真正上线仍应在采集协议中显式提供每次音频更新的序号/起始样本及对象样本偏移。

尚未用该桥接输出执行native MAT编码，不能等同于已验证所有native end时序。

480帧组包的边界
--------------
ObjectFramer可把113/367/960等片段拼成连续480帧，样本逐点守恒，缓冲最多480样本。
跨片段的位置变化保留为分段(offset,frames,xyz)，不会用一个新坐标覆盖整个块。
若同一480帧中有多个不同位置，single_position_ready=false；当前真实输入适配器会拒绝，
不会猜测native私有ABI的offset用法。尾部不足480帧也拒绝，需要明确补齐/结束策略。
本轮源全部已经是对齐的480帧，所以组包路径每条产生一个完整块、没有尾部残留。
非480帧、块内坐标时间变化目前只有合成组包测试，不是已验证任意实时回调格式。

原始节奏有界队列短测
------------------
先不限速重建前缀缓存，再回放最后600轮（源轮1378..1977，名义6.0秒）。
按每轮原始首回调QPC相对于窗口首回调的差值安排到达，不改变PCM样本时钟。
队列上限8轮（本录制每轮37条，不是native采集ring的8个slot）。
生产者put_nowait，满队列就显式失败并停止，不悄悄丢包后继续用旧坐标。
消费者由自己的Python线程执行桥接；没有任何音频线程/游戏线程参与。

结果：
  完成600轮，生产者溢出0，观察到的最高排队深度1轮，10ms完成截止超时0。
  worker每轮墙钟：P50=0.4118ms，P99=0.760427ms，最大0.9030ms。
  目标到达至完成：P50=0.7787ms，P99=1.248128ms，最大1.4525ms。

这只是Python/磁盘源离线桥接的6秒墙钟结果，不是native采集环形队列、20动态活跃对象、

自定义诊断输入二进制（全部little endian）
---------------------------------------
FILE <8sIIIIQ> 32字节：magic(MATBRG1\0或MATBED1\0),version=1,rate=48000,
  frames_per_quantum=480,frame_record_count,qpc_frequency。
FRAME <IIIIqq> 32字节：round_index,frames=480,call_count,frame_flags,first_arrival_qpc,last_arrival_qpc。
CALL <IIII3fI> 32字节：native_id,stable_source_slot,source_type,property_flags,x,y,z,frames=480，
  随后480个F32 PCM。动态volume/gain已归一到1；静态native_id=0、XYZ为NaN。
native flags 7=create+volume+position，6=volume+position，8=end。静态flags保留源值，不是动态提交指令。
这不是之前MATLIF1固定fixture，不能直接传给run-mat-lifecycle.ps1，也不会自动调用encoder。
