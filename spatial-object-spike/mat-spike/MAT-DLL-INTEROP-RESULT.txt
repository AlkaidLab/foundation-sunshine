GCC -> MSVC -> 冻结接收 DLL：实际跨进程离线验证
2026-10-21（Asia/Hong_Kong）

结论
----
此前的共享协议与独立接收 DLL 现已实际接通：
GCC 生产者 -> 匿名共享内存 32 槽 -> 独立 MSVC 普通进程 ->
冻结 DLL 的 TestMatIpcReceiverFake -> 内部 8 槽 -> 独立 codec 工作线程。
不是只核对结构尺寸，也不是在生产者进程内模拟接收。

两轮独立验证全部通过：合计 8 次完整单域回放、28 次故障场景。
每轮验证包含 normal / burst4 各两个域；每个模式完整重组出的 MATV4P1 输入，
都与以前已原生验证的 input.bin 逐字节相同。
当前验证只调用假编码回调，没有产生新的真实 MAT，不是 Android Atmos 验证。

故障覆盖（每轮14项，不混淆测试层级）
------------------------------------
  实际进入 DLL 的9项：
    contract-change=1；frame-epoch=5；frame-length=3；checksum=4；
    sequence=5；cancel=7；owner-exit=8；owner-stale=10；missing-eof=12。
    frame-epoch 在当前冻结 DLL 的合并顺序/身份检查中归类为5，
    不是旧测试夹具的2；验证器按真实分类核对，没有改写 DLL 的结果。
  包装层启动预检2项：
    header-version=1、identity=2；均在加载 DLL 前拒绝。
  包装层专用夹具3项：
    overflow=6、consumer-exit=9、consumer-stale=11。
    接收包装进程主动停读/退出，不调用 DLL；不能据此声称模拟了真实 codec 卡死。

owner-exit / consumer-exit 仅让自有测试进程主动 ExitProcess(23/31)。
生产/接收双方按预期停止；验证器用记录的 PID+创建时间核对自有子进程退出。
没有强杀进程，超时也不会自动 kill/retry。最终未发现本轮测试进程仍在运行。
另完成20项冻结 IPC 自测和23项冻结 DLL 回归；后者包含普通宿主调用真实入口
后被宿主守卫拒绝的检查，拒绝发生于 vendor/原生编码调用之前。

安全与范围
----------
启动使用 CREATE_NO_WINDOW 与显式5个继承句柄：input/data/cancel/ready/owner。
会话带 domain/epoch/nonce/PID/创建时间；宿主在本进程内另外创建有界诊断输出映射。
无全局命名共享对象，无权限/端点/驱动/安全设置变更。
共享布局4,002,112字节；测试诊断映射约49.98MB，仍不是最终常驻内存方案。
包装层不伪造 DLL 心跳，也不替 DLL 判断 owner-exit；ready 在 DLL 声明接收 PID 后发出。
校验是故障检测，不是防恶意同权限进程的密码认证。

本轮跨进程回放未调用 StartMatIpcReceiver 原生入口；无 UAC、audiodg 访问、
外部进程附加、Dolby 加载/激活、音频端点调用、真实 MAT 或 Android 解码。
普通宿主假回放 hostGuardPassed=false 是预期值，不伪造 audiodg 身份。
未证明跨 token / PPL / 真正 audiodg 句柄交付或新版私有 ABI 可用。
保留真实链路仍依赖已安装组件及版本锁定的限制。

冻结源文件核对通过：mat-ipc-receiver-build06、cpp-mat-ipc-build03、
cpp-mat-startup-build04、cpp-mat-stream-build05、mat-native-v4-build01、
cpp-native-v4-build02。旧录制与生产默认链路未修改；无关工作区修改保持原样。
