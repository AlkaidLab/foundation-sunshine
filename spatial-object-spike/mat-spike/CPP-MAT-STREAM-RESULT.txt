桥接器 -> 有界队列 -> 独立编码线程：离线验证结果
2026-10-20

结论
----
本轮完成了独立的 C++ 线程链路，使用假编码器验证接口和调度，不调用真实 Dolby。
普通回放和 10 ms 节拍回放均通过；消费线程实际收到的 PCM、XYZ、对象控制、
Process 顺序可重组为上轮真实 MAT 短测的完整 MATV4P1 输入，逐字节相同。
这验证了跨线程接缝，不代表本轮生成了 MAT，更不代表实时游戏/安卓 Atmos 已通。

本轮没有 UAC、进程附加、Dolby DLL 加载、音频激活、驱动、端点或安全设置变化。
没有修改旧桥接器、采集器、原生 MAT 探针或其冻结构建/输入；没有修改生产默认链路。

实现文件（本目录）
------------------
cpp_mat_stream.hpp          固定大小快照、Boost SPSC、Pipeline/Encoder 接口
cpp_mat_stream_fake.hpp     只记录调用的假编码器，强制所有接口在独立线程执行
cpp_mat_stream_tests.cpp    新增生命周期、并发、错误与边界测试
cpp_mat_stream_replay.cpp   真实 v4 录制 -> 原有 DomainBridge -> 快照 -> 消费线程
build-cpp-mat-stream.ps1    复用现有 FFmpeg/Boost，无依赖安装
verify_cpp_mat_stream.py    独立 Python 字节级核对与内存负控

链路与所有权
------------
录制解析/桥接线程 -> 自有 PCM+XYZ 快照 -> 每域 8 槽 SPSC -> 每域独立编码线程

沿用既有 v4 DomainBridge/PositionCache/FFmpeg AVAudioFifo；增益只在桥接处执行。
快照连同样本、坐标、ID、生命周期和帧序号复制，不持有桥接器输出的悬空指针。
编码器接口强制 volume=1、callGain=1，不重复施加增益。
open、submit、process、close 全由编码线程执行；队列等待用原子通知，不做 1 ms 空转。
每个域独立对象状态、队列、编码器和输入时钟，不按 QPC 猜测跨域样本同步。

tryPush 是单生产者尝试入队接口，无显式等待/容器分配，满队列不覆盖也不跳帧。
满队列或序列缺口使本 epoch 失败，失败输出不可播放/拼接；必须结束旧线程、
显式创建新的 Pipeline/编码器 epoch，不能沿用旧缓存静默恢复。
普通 C++ 原子通知/线程机制不是已证明的音频实时钩子实现，不能直接据此声称硬实时。

pushOffline 是独立的离线送料包装，可等待空位，默认最多 5 秒，超时取消。
它不能在 audiodg 音频线程/钩子中调用。消费中的外部编码器调用本身不可被安全抢占；
join/析构是控制线程操作，不是实时操作，未来真实适配器还需要独立故障/存活边界。

生命周期
--------
保留录制开头的空 Process；第一次已知对象出现时，先按相同 ID/XYZ 创建对象、
喂 20 轮静音预热，随后原始 create 转为 update。其他创建不额外重复预热。
后续源 Process 不合并、不跳过；EOS 最后一段 PCM 由原桥接器保留，end 控制在下一轮。
EOF 是控制消息，不计为源 Process 或样本推进；EOF 内尚有的 end 控制并入首个 drain。
明确执行 30 轮 drain 后关闭。空域不凭空创建对象。
ID 重复、未知 update/end、非有限 PCM/XYZ、超过 20 个活对象、仍活对象突然缺席均拒绝。

固定队列内存
------------
单快照 124,968 字节（最多 64 个调用，包含退役控制余量）；可用 8 槽。
可用载荷 999,744 字节；Boost 内部另有一个环形保留槽，实测 sizeof(Queue)=1,124,784。
此外有生产者/消费者暂存快照、FFmpeg FIFO 和 worker 容器，不把队列大小当作总进程内存。
假编码器为离线对照保留完整调用记录，内存随录制增长，不是最终常驻输出实现。

限制与下一个真实接入前的门槛
--------------------------
1. 录制预加载，送料可以背压；10 ms 模式只验证独立消费者节拍下的内容不变，
   没有逐轮硬实时期限/CPU/编码延迟结论，也没有新游戏实战或常驻长测。
2. 8 槽只缓存约 80 ms 源轮，不能掩盖 200 ms 预热。在实时接入前必须明确上游
   有界预缓冲/启动门控或其他经过验证的预热策略，不能把 pushOffline 搬进钩子，
   也不能通过丢首帧/伪造静音掩盖这个问题。
3. 真编码器仍在 audiodg 中；本轮只是定义并验证 Encoder 接口，没有让普通进程
   获得直接调用私有 Dolby 编码器的能力。跨进程共享队列和真正 native adapter
   仍需单独实现、离线测协议，再经新的明确授权做短原生复测。
4. 编码后 XYZ 校准、元数据/音频同步、认证 MAT 解码、Android 本地 Atmos 均未新增验证。
