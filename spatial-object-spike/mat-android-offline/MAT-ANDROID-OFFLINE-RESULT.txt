MAT Android client A/B: shared receiver + independent IEC61937 output
2026-10-21

Scope
-----
A/B host-side acceptance only. No Android device, AudioTrack hardware execution,
HDMI/eARC receiver, Atmos decoding, object rendering or latency measurement.
The standalone diagnostic APK uses the actual new Android client classes/JNI,
but is NOT a complete Moonlight APK. No new RTSP playback codec is negotiated.
Existing AUDIO_CODEC_MAT_DUMP=4 remains dump-only and never opens AudioTrack.

Implementation
--------------
1. MatReceiver.h/.c, present in both common-c checkouts:
   Consumer-independent complete-cycle reception, epoch/domain/index/PTS metadata,
   terminal errors, explicit EOS, separate SMAT and offline-recording modes.
   MatDumpFile uses this receiver while keeping its file/SHA/publish lifecycle.
   MatDepacketizer, SMAT wire format and existing dump profile are unchanged.

2. MatNativeReceiver.java + mat_carrier_bridge.c:
   Dedicated synchronous JNI bridge with a 61,440-byte reusable sample array.
   Does not use the existing 16KB AC3/E-AC3 sample callback or create a decoder.
   Handles are serialized and explicitly closed. Consumer rejection is terminal.

3. MatCarrierPlayer.java:
   Android-independent state machine, four-cycle bounded output FIFO,
   preallocated six-slot pool, independent writer thread, copy-before-return.
   Little-endian bytes are reinterpreted as shorts without another byte swap.
   Nonblocking partial writes retain exact offsets; only accepted bytes are hashed.
   Zero progress, bad write counts, sink errors and queue overflow fail explicitly.
   EOS drains written carrier frames before release; timeout cannot report success.

4. MatAudioTrackSink.java:
   ENCODING_IEC61937 / 192000Hz / CHANNEL_OUT_7POINT1_SURROUND / MODE_STREAM.
   Android API24 minimum, API33+ direct bitstream gate, initialized-track check,
   HDMI route and audio-focus checks, unsigned/wrapping playback-head accounting.
   Buffer is at least two complete cycles and the reported minimum, rounded to
   whole cycles. Rejects a minimum over sixteen cycles (320ms diagnostic limit).
   Route is checked periodically; there is no PCM fallback, DSP, resampling,
   system spatializer, downmix, normalization or touch/haptics processing.
   Uses application-local audio focus; never modifies global sound settings.

5. MatRecording.java + debug-only MatReplayActivity:
   Reads only the frozen 178-cycle fixture, bounds size, checks full SHA256 and
   carrier headers BEFORE opening any output. Then supplies source cycles at
   an absolute 20ms cadence; a whole-cycle timing stall rebases instead of bursting.
   Output startup completes before source delivery begins. Stop/pause cancels.
   New standalone APK includes the frozen fixture, so TV document pickers are
   optional. Ordinary Moonlight release builds have no new launcher/test activity.

Clock contract
--------------
61,440 bytes = 30,720 words = 3,840 eight-channel carrier frames = 20ms.
SMAT logical PTS remains index*960 at 48,000 ticks/s.
AudioTrack hardware frame clock is 192,000 frames/s.
Do not use RTP/FEC fragment timestamps or logical 48kHz as AudioTrack parameters.
Do not pass this already-framed recording into Kodi's TrueHD MAT packer.

Acceptance run: run05/
---------------------
JVM -Xcheck:jni executes the actual production native receiver/JNI and Java player.
Only the final hardware sink is fake; Android AudioTrack itself is not executed.
12 test groups:
- Bounded full recording verification; truncation/trailing bytes/SHA mutations.
- Whole recording -> native JNI -> player -> partial/zero writes -> independent SHA.
- All SMAT fragments -> receiver -> JNI -> player; in-cycle reorder/duplicates/EOS.
- Bounded queue overflow fails without silently dropping.
- Zero-progress timeout, negative/DEAD_OBJECT-like error, invalid write count.
- EOS waits for the fake hardware playhead before release.
- Frozen playhead cannot complete EOS successfully.
- Cancellation joins the writer and releases its sink even when its owner is
  already interrupted, then restores the owner's interrupt flag.
- Borrowed JNI array overwrite after callback does not corrupt queued bytes.
- Bad size/header/PTS/epoch/domain/consumer/EOS, packet corruption, conflicting
  duplicate, missing fragment, cross-cycle gap and mixed mode are sticky failures.
- Closing without EOS does not invent a successful EOS.
- Double close and use-after-close are safely handled by the Java owner.

Both full-fixture paths submit all 178 cycles / 10,936,320 bytes and match the
source SHA256 in both the player accounting and independent fake sink hash.
run05 recording submission elapsed 3571ms, peak pending queue 1/4.
This is an offline source-cadence observation, NOT Android end-to-end latency.

Reproduce from repository root (PowerShell)
-----------------------------------------
./spatial-object-spike/mat-android-offline/verify.ps1 -Output <NEW_DIRECTORY>
Requires local JDK22, Android SDK36/build-tools36/NDK28.2 and MSYS2 UCRT64 tools.
The dump regression compiler reuses the existing Sunshine compile_commands.json.
The script never installs software or connects to a device. Each run needs a new
output directory; previous test artifacts are not deleted or overwritten.
