## 当前已实现、尚未验收的边界

- 实验能力需构建、主机设置及连接协商分别通过；观测不授予控制。GoogCC 接管需要实际应用、首发和新鲜成功发送覆盖。
- 网络预算、净编码目标和队列编码上限分开，手动 RS 固定。原始丢包分母只含实际成功提交，未知和未发预留身份不冒充丢包。
- 所有视频使用有界 owner；兼容策略为原 800 Mbps 速率、64 KiB 突发和 1 秒期限，不能宣称兼容会话受新总预算保证。实验归一化策略采用其预算及默认 100 ms 期限。
- 所有共享 socket 音频复用 256 包/256 KiB、入队后 40 ms 的非阻塞队列；提交前复查停止、期限与已有许可，发送线程退出后关闭 socket。此次生命周期修正仅有编译与组件证据，真实混合客户端播放、停止和出口故障仍待验收。
- 固定 SDK 的原生探测、loss recovery 与持续 padding 已接真实身份、成功回执和媒体优先级；有效估计与容量恢复不能由“请求已生成”或“簇已提交”推出。
- 真实后端失败、DXGI 失效、同步捕获停止等已接既有错误/重建路径，但组件夹具不覆盖所有硬件、驱动与多会话故障。

## 容量恢复与公平性的原结果

原容量观察要求 `confirmed.wireBudgetKbps ≥ 19000` 连续五秒。该值不是接收吞吐或画质，五秒是保持窗口，不是恢复时限；以下原结果均保持原判据。

| 版本与条件 | 原结果 | 当前解释 |
| --- | --- | --- |
| `c2d80af7` / `d6c388ff` 的软件队列 | 完整上限观察失败；恢复请求曾均因媒体不足取消 | 不能归为链路容量不足，不能以生成探测请求代替实际发送 |
| `99ac0ac6`、原生持续 padding 与后续媒体优先修正 | 有真实簇、估计和持续 padding；原上限观察仍失败 | 真实探测已发送不能单独证明恢复；不把各版流量差异作收益对比 |
| `d0e97f9d` 的已校准 TBF、未冻结桌面 | 确认预算最高 19975 Kbps，合格连续 17.9528992 秒，原预算子项通过 | 不扩大为完整 P2、媒体供给资格或 QoE；软件队列/netem 失败不改判 |
| `e55830af1` 固定源默认/回压 | 默认 0 秒失败，回压 7.9612735 秒子项通过 | 两场预算历程不同，没有同预算收益结论 |
| `580e70aed` 固定源默认/回压 | 4.3701394/2.925332 秒，均失败 | 不能用末态接近 20 Mbps 代替连续窗口 |
| `e6c55dc84` 六轮，默认/回压各三轮 | 默认 0/3、回压 1/3；分别 0、0、0、24.8721949、0.9062237、4.9778206 秒，重复验收失败 | 4.9778206 不四舍五入为五秒，所有运行保留 |
| `7ffeb7937` 六轮 | 默认 1/3、回压 1/3，重复验收失败 | 不用成功单场覆盖全部重复条件 |
| `8427249a5` 默认三轮 | 原预算观察 2/3；两轮共 41 个成功源包批次超期，最大 134 µs、涉及五帧 | 原期限失败仍开放，不追认新恢复目标通过 |
| P2-v2 恒定链路基线，`c7c0679d2` | 三轮内容/时钟/账本资格通过，运动交付 10.735/15.612/9.490 单元每秒；共 35 个超期回执，最大 69 µs | 原严格 100 ms 检查三轮失败；随机纹理压力源不代表普通业务需求 |

多会话公平性原条件为稳定十秒后五秒窗口：实际交付至少瓶颈 90%、入口至少 105%、至少三个合格窗口，Jain 至少 0.90、各端份额至少 25%。D0/E6 等双会话核对已证明计费/解码/停止隔离；E6 的合格饱和窗口为 0/5，公平性证据不足。未饱和的 Jain 或预算隔离不记为公平性通过。

P2-v2 将业务恢复、合法低/零产出与具备激励资格的容量发现分开，执行顺序和冻结要求见[实施文档](adaptive-fec-implementation.zh-CN.md#p2-v2业务恢复与容量发现2026-10-07)。缺少匹配基线、需求/可达份额、渲染观测或事前容限时保持待验收；不能用降档后的低生产率重定义需求，也不能事后放宽 100 ms、预算、身份或资源约束。
