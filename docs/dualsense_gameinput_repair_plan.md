# DualSense 历史 GameInput 映射修复实施计划

本次修复针对普通 DualSense USB 设备 `054C:0CE6` 遗留的错误 GameInput 映射，同时恢复轴、按钮和 Windows 手柄导航。交付内容包括 Core 清理保护、可独立运行的定向修复入口、控制面板操作与回归测试。

采用“自动检查和保护，显式备份和修复”的策略。匹配旧 SDK 模板说明配置可以被识别，不等于证明它归 Sunshine 所有。修复不依赖 sidecar 曾经启动，也不要求用户建立虚拟手柄会话。

状态：已实现 Core 保护、独立修复和控制面板入口；内部回归已通过，Windows 导航和候选版本实机验收仍单列跟踪。证据基线为 2026 年 11 月 6 日收到的 [用户验证回复](https://github.com/AlkaidLab/foundation-sunshine/issues/1056#issuecomment-6682980661)及其中两份报告。

## 已确认的修复范围

用户在 Windows 11 `26300.9818`、实体 DualSense USB 直连环境验证了三个轴索引修正：静置 1817 次采样中左右扳机均为零，右摇杆 Y 接近中心；幽灵导航消失，正常导航保留。拔插两次、Sunshine 重启和一次普通串流前后映射均未改变。

逐键采样还确认了四个按钮映射错位。下表是本次实现的目标；四个按钮的新映射需在候选版本验收时验证，不能标为用户已经应用并通过。

目标位置为 `HKLM\SYSTEM\CurrentControlSet\Control\GameInput\Devices\054C0CE600010005\Gamepad`。

| 子键 | 值名 | 旧值 | 目标值 |
| --- | --- | ---: | ---: |
| RightThumbstickY | AxisIndex | 3 | 5 |
| LeftTrigger | AxisIndex | 4 | 3 |
| RightTrigger | AxisIndex | 5 | 4 |
| View | ButtonIndex | 6 | 8 |
| Menu | ButtonIndex | 7 | 9 |
| LeftThumbstickButton | ButtonIndex | 8 | 10 |
| RightThumbstickButton | ButtonIndex | 9 | 11 |
| A | ButtonIndex | 0 | 1 |
| B | ButtonIndex | 1 | 2 |
| X | ButtonIndex | 2 | 0 |

实施时发现计划还遗漏了面键语义：原生编码的 Cross 对应原始按钮 1，Circle 对应 2，Square 对应 0。用户报告的 raw 0→A 只说明旧表映射关系，不能作为物理面键正确的证明。因此增加 `A=1`、`B=2`、`X=0`，并用实际 Sony 报告编码测试对照；总计修复三个轴和七个按钮。其他轴、Invert、Y、肩键和方向键映射保持原值。用户报告的“20 项”指 Gamepad 下的映射项，不是整棵设备键只有 20 个值；备份和识别都必须检查完整设备键树及值类型。

本次不扩大到 Edge、蓝牙、其他 Sony 型号，也不修改 HID descriptor 或输入报告布局。HIDMaestro 继续固定 v1.12.0，2.x 共存升级单独处理。原始 sidecar 场景仍需要内部验证，不能由实体手柄报告代替。

## 映射识别和操作规则

分类器读取完整树，比较键名、值名、类型和数据；只允许在十个目标字段上存在已定义的差异。保留默认值和附加子键的检查，不能仅凭 VID/PID、三个轴值或键数量判定。

| 状态 | 检查结果 | Core 自动清理 | 显式修复 |
| --- | --- | --- | --- |
| mapping_missing | 设备映射不存在 | 不创建 | 报告缺失；仅支持从有效备份恢复 |
| legacy_mapping | 完整匹配旧版独立扳机模板 | 保留并报告可修复 | 备份后修正十项 |
| axes_fixed | 完整匹配旧模板，仅三个轴已改为目标值 | 保留 | 备份后修正七个按钮 |
| navigation_fixed | 原计划的三个轴和四个按钮已修正 | 保留 | 备份后修正 A/B/X |
| corrected_mapping | 十项均正确，其余完整匹配 | 保留 | 无操作，不重复备份或写入 |
| custom_mapping | 附加内容、其他值或类型不符 | 保留 | 输出差异，不覆盖 |
| access_denied | 无法完整读取 | 不修改 | 明确报告读取或权限失败 |
| recovery_required | 有本工具未完成的操作记录 | 保留 | 核对记录后恢复或继续，否则报告冲突 |

旧版 combined-trigger 模板、仅部分手工修改的未知组合均不按普通 DualSense 自动修正；由诊断报告保留其差异。中断产生的部分状态仅凭有效操作记录恢复，不能放宽模板识别来猜测。

缺失表不视为“输入健康”，不从十个目标索引推造整张映射。已经被旧清理删掉且没有备份的配置，无法恢复其原始定制内容；本次交付必须明确显示这一状态。

## Core 清理保护

新增独立补丁 `tools/hidmaestro-core-patch/dualsense-gameinput.patch`，应用到当前固定源码。为分类器增加单一共享源码，由 Core 和 sidecar 使用，避免 SDK 清理与修复命令采用不同判定。

在所有可能删除、认领或恢复 GameInput 表的位置执行同一保护规则：

- `RegistryLedger.RemoveLegacyTable`：按身份清理。
- `RegistryLedger.RemoveLegacyTables` 和 `GameInputMapping.RemoveLegacyTables`：全量清理。
- `RegistryLedger.RestoreGameInput`：正常释放、崩溃回收及 ReleaseAll 最终调用的恢复路径。
- `RegistryLedger.ClaimGameInput`：审查已有表被删除重建及持有记录存在时重新写表的分支。
- `DeviceOrchestrator.ApplyGameInputMapping` 及完整清理入口：核对调用顺序，确保保护先于删除生效。

普通 DualSense 的可识别旧表在自动清理中改为保留，显式修复完成后仍然保留。其他身份的现有清理行为保持原样，JSON profiles 继续不自动生成 GameInput 表。活动或无法确认已结束的 ledger holder 阻止显式迁移。

`--probe` 和正常状态刷新保持只读，不在 HMContext 构造、设备创建、卸载或自动组件升级时隐式修正十个值。自动路径只报告状态并保护现有配置。

增加独立 Core 能力标记，例如 `FoundationDualSenseGameInput=preserve-v1`。sidecar 在进入 SDK 路径前检查该标记，避免新命令搭配仍会删表的旧 Core。

## 定向修复和备份恢复

在 `tools/sunshine-ds5-sidecar/Program.cs` 增加检查、应用和恢复命令，建议接口为：

```text
Sunshine.Ds5Sidecar.exe --gameinput check --result <report.json>
Sunshine.Ds5Sidecar.exe --gameinput repair --result <report.json>
Sunshine.Ds5Sidecar.exe --gameinput restore --backup-id <id> --result <report.json>
```

命令在创建 HMContext、安装驱动或创建虚拟设备之前分流。检查无需驱动和虚拟设备；写操作要求管理员权限，并由现有管理操作流程保证无活动串流。操作前要求用户退出占用目标手柄的程序并拔下目标实体手柄；阻止已知活动虚拟设备或 holder 下的迁移。

修复流程按以下顺序执行：

1. 获取与上游 registry ledger 协调的锁并检查 holder；读取完整树，进行严格分类。
2. 把完整树、值类型、目标路径、迁移版本、原始摘要和十项目标变化持久化到管理员可写的备份目录。目录使用固定的 ProgramData 子路径，不接受任意注册表目标。
3. 备份成功后重新核对快照；有变化即报告冲突。写入操作记录后，仅打开已存在的十个字段所属子键，修改实际需要变更的 DWORD。
4. 回读完整树，确认十项正确且其他内容不变，再标记提交成功。报告包含备份 ID、逐项变更、状态和 `restart_required`。
5. 失败时依据操作记录，只撤销仍等于本次写入值的变更。发现外部修改则保留现场并报告冲突，不执行整树覆盖。

操作记录需覆盖任一字段写入后崩溃的恢复；多字段注册表写入不能宣称具有事务原子性。共享锁只能协调遵守它的程序，仍需前后快照校验以发现其他写入。

备份文件记录完整设备树，不包括无关注册表。恢复命令使用固定目录内的备份 ID，验证格式、目标白名单和记录完整性；现有表只恢复本次改过且仍符合提交快照的字段。若设备键已整体缺失，只有在备份被验证且用户显式选择恢复后才重建备份树；未知半缺失或冲突状态不覆盖。

修复成功显示“映射已修正，需要重启 Windows 后验证”。不自动重启、停止 GameInput 服务或重新枚举设备，也不把注册表回读通过标成 Windows 输入验收通过。恢复旧配置需提示其可能重新引入已修复的症状。

## 控制面板和组件交付

控制面板在控制器诊断区域增加“检查桌面手柄输入”和检查后出现的“修复映射”动作，支持按备份 ID 恢复。用户只需看到可修复状态、修改目的、备份和重启提示；具体注册表差异放入诊断详情。

- 在 `src-tauri/src/dualsense/commands.rs` 增加命令，复用组件操作锁、空闲检查、组件完整性验证。
- 在 `elevated.rs` 增加限定的 RepairGameInput 和 RestoreGameInput 操作，复用现有 UAC 和本地管道，不建立第二套提权器。
- 检查状态从独立检查命令获取，不把新字段塞进全等比较的 `component-compatibility.json`。没有合格组件时先走现有组件安装或更新；不要求安装 USB/IP 或创建虚拟手柄来修复实体手柄映射。
- 自动组件更新只交付能力及刷新检查结果；映射写入来自用户点击修复。卸载和组件目录回滚不自动撤销系统映射。
- 更新 Core 构建补丁列表、程序集能力验证、组件版本、完整 ZIP 摘要、manifest 与 GUI 子模块 pin。版本使用实施时尚未占用的新组件版本，保留 ZIP 校验及整包回滚流程。

主仓库与控制面板分为配套变更，但作为同一次功能交付。现有 `packages.lock.json` 修改以及当前载荷策略工作不并入本次提交；从确定的集成基线建立独立分支。

## 测试和验收

### 隔离注册表回归

扩展 `tools/hidmaestro-core-patch/PayloadTool/Program.cs` 的现有隔离 HKCU 测试，直接调用生产分类器和迁移逻辑，不访问真实系统 GameInput 表，不运行驱动安装或 PnP 清理。

- 完整旧表迁移十项；用户已修三轴的表只迁移七个按钮；完整正确表重复运行零写入。
- 缺失表、附加子键或值、错误类型、未识别部分改表和非目标 VID/PID 均不被定向修改。
- 四种目标表通过按身份清理、全量清理、release/prune 恢复及 claim 路径后仍被保护；其他型号旧表保留原有处理。
- 活动或不确定 holder、备份失败、权限失败、快照冲突不会留下成功结果。
- 对十项中的每个写入点注入失败或中断，覆盖回滚、继续执行、外部改动冲突和有效备份恢复。
- 备份保留所有值类型及内容；输入备份格式错误、目标不符和路径越界均拒绝。

旧测试中针对普通 DualSense 的“精确旧表必须消失”断言改为“表仍存在且可修复”；增加其他身份用例，确认没有顺带关闭全部旧表清理。

### 无实体手柄的 Windows 验证

在可还原的 Windows 测试环境创建虚拟 DualSense，发送中立报告和逐项输入，读取实际 RawGameController 与 WGI 结果。系统行为验证使用测试环境中的真实 HKLM 映射；进程内 HKLM 重定向仅用于隔离回归，不能验证系统服务或 Shell。

覆盖错误表、三轴已修表和完整修正表，以及当前 HID-only USB/IP 与 composite 两条路径。需要覆盖旧 UMDF 兼容路径时，单列使用相应历史组件的测试结果，不改动当前传输策略来伪造覆盖。

验收要求：静置不产生持续导航；LT/RT 为零、摇杆接近中位；逐轴输入不串轴；L2/R2 不额外触发 View/Menu；View/Menu/L3/R3 正确；释放后复位；设备创建和销毁后映射不变。未枚举到 Gamepad 是单独结果，不计为零输入通过。

WGI 采样通过后另行验证 Win+A 的静置和实际导航。SDK 自检、原始 HID 报告正确和注册表回读正确均不能代替此项。

### 用户候选版本验收

我们完成内部测试后再提供候选版本，用户无需继续收集泛化诊断材料。请用户在已修三轴的现有环境执行一次定向修复，确认报告只修改七个按钮，包含 A/B/X，并验证：

1. 重启 Windows 后不滚动，正常导航保留。
2. L2/R2 不触发菜单，Share、Options、L3、R3 独立正确；Cross、Circle、Square、Triangle 分别对应 A、B、X、Y。
3. 拔插两次及 Sunshine 重启后结果保持。

sidecar 场景优先由内部虚拟设备测试完成，不要求用户为此先修复其 motion server 或改变串流配置。

## 当前环境的系统验收边界

内部测试仅向临时 HKCU 子树写入；本机真实 GameInput 映射未修改。当前环境没有 Windows Sandbox，当前身份无 Hyper-V 管理权限，也不能执行需要管理员权限的设备自测。因此 WGI 与 Win+A 的系统行为、真实 UAC 交互及用户重启验收仍需在可用测试环境或候选版本上完成；这些项目不得记为通过。独立检查命令已在无实体手柄环境验证为只读，并正确报告 mapping_missing。

内部验证结果：114 项映射和恢复检查通过，包含十个写入位置的进程中断恢复及备份 ACL 检查；原生报告编码验证了目标按钮顺序。控制面板 56 项 Rust 回归、153 项前端测试和 1 项实际构建组件契约测试通过，生产前端构建和完整组件打包通过。写入前校验失败时撤销未开始的操作记录，崩溃子进程使用当前测试主机路径。模拟修复中断后检查失败的 UI 验证通过：保留恢复备份入口，撤掉过期的修复状态。配套控制面板 PR 为 [188](https://github.com/qiin2333/sunshine-control-panel/pull/188)。
