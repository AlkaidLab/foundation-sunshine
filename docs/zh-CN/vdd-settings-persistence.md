# 保存旧版 VDD 设置

[开发](development.md) · [English](../en/vdd-settings-persistence.md)

配置 API 会将公布的分辨率、刷新率和 GPU 选择保存到 Sunshine 配置和现有 VDD 模式/GPU XML。
以前 XML 写入失败可能被忽略，或后续主机配置写入失败导致只有 XML 更新。并发请求也可能交错写入。

现在保存操作在现有配置互斥锁内暂存 XML 并写入主机配置。
XML 写入失败会返回给调用方，且不会提交主机文件。
主机写入失败时，会在释放锁之前恢复原始 XML 字节。无关 XML 设置会保留。
XML 不存在时不执行 XML 保存：API 仍保存 Sunshine 设置，不创建驱动配置文件。

这是尽力而为的错误恢复，不是可应对崩溃的跨文件事务。回滚失败会记录日志。
API 报告保存失败时，请检查主机日志，解决文件访问问题后重试。
此变更不会重启主机、重装驱动或重新创建显示器。

## 模式列表值

对于 `resolutions` 和 `fps`，省略字段、空字符串、JSON null 或字符串 `"null"` 都会保留已保存的列表。
磁盘上的列表也不存在、为空或 null 时，使用主机当前公布的运行时列表。两个配置文件会保存相同的有效值。
明确提交带方括号的空列表 `"[]"` 会清空列表，由驱动使用现有后备模式。
后续省略、空或 null 值会保留这个明确清空的列表。

列表字段仍为字符串，例如：

```json
{"resolutions":"[1920x1080,3840x2160]","fps":"[60,120]"}
```

这只是字段片段，不是完整 API 请求。`POST /api/config` 仍会替换其他非受保护设置；请提交完整配置以保留这些字段。
现有受保护字段和客户端字段规则保持不变。

此保存路径变更不包含 EDID 首选项、显示器创建协议或签名驱动依赖，可以独立于 EDID 原生尺寸选项审查。
