# 动态 RS FEC 与客户端指定比例

实现范围仅包含：根据客户端反馈自动选择 RS 冗余比例，以及客户端指定本会话的固定比例。客户端指定值优先于自动选择和主机默认值。移除了本分支新增的 GoogCC、逐包身份、带宽探测、自动码率、发送预算、发送队列、帧调度和 UDP 提交改造；主干已有的码率功能保持原样。

## 使用

PC 的基本设置、Android 的基本设置提供 FEC 模式：跟随主机、自动、固定。固定比例为 0–100，0 表示关闭视频 RS 保护。设置在下一次连接时提交；旧主机不支持该扩展时使用原行为。PyroWave 保留原有独立保护，不使用这个 RS 控制器。

主机可配置：

```ini
fec_percentage = 20
fec_auto = false
fec_auto_max_percentage = 50
```

默认行为仍是主机固定比例。客户端选择自动后，在有新鲜反馈时自动选择；客户端固定值优先。主机 `fec_auto` 仅决定“跟随主机”模式是否自动，`fec_auto_max_percentage` 是自动选择上限，不限制客户端明确指定的固定值。

公共库 `STREAM_CONFIGURATION.videoFecPercentage` 为 -2（跟随主机）、-1（自动）或 0–100（固定）。调用 `LiInitializeStreamConfiguration` 获取兼容默认值。运行中的控制连接可调用 `LiRequestVideoFec` 修改；成功仅表示可靠控制消息已提交。现有配对 HTTPS `/stream/settings` 的 FEC 参数类型 4 接受相同数值，仅允许修改证书所属、名称匹配且唯一的活动会话。

## 自动比例选择

复用既有客户端 RTP FEC 队列。每个已观察到的块结束时，累加原始数据分片总数和恢复前缺失的数据分片数；成功且无需恢复的块也进入分母。每秒通过既有加密 ENet 控制连接发送一条 12 字节汇总，不修改视频 UDP 格式，不新增逐包身份或发送账本。

这些计数表示“块完成或放弃时的数据分片缺失”，不是面板的视频丢帧率，也不等价于物理链路丢包率。迟到及乱序可能进入缺失计数，完全没有观察到的帧不进入分母。反馈缺失不制造丢包；超过 3 秒没有有效样本时使用主机固定值。

主机使用平滑后的缺失比例和实际待发送帧大小，调用已有 Boost.Math 的二项分布尾概率。对可表示的 RS 布局选择最低冗余，使独立同分布丢失模型下“一帧任意块不可恢复”的概率上界不超过 0.1%。这是模型目标，不是实际体验保证；相关丢失、发送突发、迟到和未观察帧都可能偏离该模型。没有突发丢包分类或专用适配。

自动选择受比例上限及现有 RS 协议限制约束。无法达到模型目标时采用上限内最高可表示比例。客户端固定比例不会被自动算法改写；若固定值无法放进最多四个、每块总计不超过 255 分片的 RS 布局，保持原有跳过 FEC 的回退并记录日志。每帧仅选择一次比例，整个帧不被中途更新的设置改变。

冗余相对数据定义：`P = ceil(D × F / 100)`。自动上限约束名义请求比例；最低冗余和整数取整可能增加实际比例，不能把名义上限当作实际流量上限。最低冗余和线上的整数百分比必须可相互还原。较大的未保护块仍受 10 位分片索引限制，超过协议范围的帧被拒绝，不能截断发送。

FEC 增加实际发送数据量。本实现不重新分配编码器码率，也不承担拥塞控制或链路容量发现。测试必须在相同编码器和码率设置下比较基础流畅性、恢复收益及额外流量。

## 协议边界

主机 DESCRIBE 广告 `x-ss-video[0].fecControlVersion:1`。客户端仅在版本匹配且为旧 RS 视频格式时提交 `x-ml-video.fecSummaryVersion:1` 和 `x-ml-video.fecPercentage`。

- `0x5510`：客户端 FEC 汇总，三个大端 uint32：序号、数据分片数、缺失数据分片数。
- `0x5511`：客户端模式请求，一个小端 int32，数值为 -2、-1 或 0–100。

汇总使用普通非可靠控制消息，每条仅结算自身窗口；丢失报告不扩大下一条分母。序号用于拒绝重复和倒退，并允许 uint32 回绕。无效数量、旧报告及错误长度被拒绝。固定模式请求使用可靠控制消息。消息归属复用现有控制连接和认证，不引入新的控制租约。

## 验证

一个主机测试文件覆盖：客户端固定优先、会话隔离、自动选择和上限、失效反馈回退、无效/重复/倒退/回绕报告，以及 RS 分块、最低冗余和线上的百分比一致性。复用公共库现有回归；不保留原方案的大型回放样本或 SDK 测试入口。

当前已完成核心单测和公共库 Release 编译回归。完整主机/客户端构建、旧客户端与旧主机组合，以及真实设备的基础流畅性和相同码率恢复收益仍需验证。旧体验包的通过记录不用于声明本次收敛通过。
