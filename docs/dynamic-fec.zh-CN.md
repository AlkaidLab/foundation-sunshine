# 动态 RS FEC 与客户端指定比例

实现范围包含根据客户端反馈自动选择 RS 冗余比例、客户端指定本会话的固定比例，以及两者对应的编码码率预算分配。客户端指定值优先于自动选择和主机默认值。复用主干已有的手动码率和 ABR 入口；移除了本分支新增的 GoogCC、逐包身份、带宽探测、发送队列、帧调度和 UDP 提交改造。

## 使用

PC 的基本设置、Android 的基本设置提供 FEC 模式：跟随主机、自动、固定。固定比例为 0–100，0 表示关闭视频 RS 保护。设置在下一次连接时提交；旧主机不支持该扩展时使用原行为。PyroWave 保留原有独立保护，不使用这个 RS 控制器。

主机在 **Web UI → 配置 → 网络** 中提供三个可见选项：

- **自动 FEC**：默认关闭，决定客户端“跟随主机”时是否自动选择。
- **默认/回退 FEC 比例**：默认 20%，范围 0–255%，0 表示关闭；无可用反馈或反馈超过 3 秒时采用此值。
- **自动 FEC 比例上限**：默认 50%，范围 0–100%，也适用于客户端主动选择自动模式。客户端固定比例不受此上限限制；整数取整及最低冗余可能增加实际开销。

通过界面保存并应用配置，然后重新连接串流。后续实机验证通过这些可见选项和客户端基本设置切换模式，不依赖手工编辑配置文件或隐藏实验开关。

默认行为仍是主机固定比例。客户端选择自动后，在有新鲜反馈时自动选择；客户端固定值优先。主机 `fec_auto` 仅决定“跟随主机”模式是否自动，`fec_auto_max_percentage` 是自动选择上限，不限制客户端明确指定的固定值。

公共库 `STREAM_CONFIGURATION.videoFecPercentage` 为 -2（跟随主机）、-1（自动）或 0–100（固定）。调用 `LiInitializeStreamConfiguration` 获取兼容默认值，设置在下一次连接时协商提交。

## 自动比例选择

复用既有客户端 RTP FEC 队列。每个已观察到的块结束时，累加原始数据分片总数和恢复前缺失的数据分片数；成功且无需恢复的块也进入分母。每秒通过既有加密 ENet 控制连接发送一条 12 字节汇总，不修改视频 UDP 格式，不新增逐包身份或发送账本。

这些计数表示“块完成或放弃时的数据分片缺失”，不是面板的视频丢帧率，也不等价于物理链路丢包率。迟到及乱序可能进入缺失计数，完全没有观察到的帧不进入分母。反馈缺失不制造丢包；超过 3 秒没有有效样本时使用主机固定值。

主机使用平滑后的缺失比例和实际待发送帧大小，调用已有 Boost.Math 的二项分布尾概率。对可表示的 RS 布局选择最低冗余，使独立同分布丢失模型下“一帧任意块不可恢复”的概率上界不超过 0.1%。这是模型目标，不是实际体验保证；相关丢失、发送突发、迟到和未观察帧都可能偏离该模型。没有突发丢包分类或专用适配。

自动选择受比例上限及现有 RS 协议限制约束。无法达到模型目标时请求上限内最高可表示比例；发送比例还受该帧编码时已生效的 FEC 预算限制，预算协调期间可能暂时低于模型要求。客户端固定比例不会被自动算法改写；若固定值无法放进最多四个、每块总计不超过 255 分片的 RS 布局，保持原有跳过 FEC 的回退并记录日志。每帧仅选择一次比例，整个帧不被中途更新的设置改变。

冗余相对数据定义：`P = ceil(D × F / 100)`。自动上限约束名义请求比例；最低冗余和整数取整可能增加实际比例，不能把名义上限当作实际流量上限。最低冗余和线上的整数百分比必须可相互还原。较大的未保护块仍受 10 位分片索引限制，超过协议范围的帧被拒绝，不能截断发送。

## 会话码率预算

客户端码率和 ABR 更新统一表示串流目标预算，经过主机上限约束后保存到会话；性能面板和会话接口展示该预算，不从编码器码率反推实际流量。启动、手动调整、ABR 和编码器重建复用 `streaming::bitrate_budget_t`。先扣除已有音频及协议预留（分别最多 20% 和剩余预算的 10%），再按 `编码码率 = 视频预算 × 100 / (100 + F)` 分配。固定模式采用客户端值或主机值；0% 不预留 RS 冗余，100% 的名义视频预算由数据和冗余各占一半。旧客户端没有发送总预算时保留初始编码目标的兼容推算。

自动模式以一秒窗口内的最大请求比例协调预算，忽略单个百分点振荡，但允许启用保护和回到 0%。比例提高时，编码线程成功降低编码目标后，新提交的帧才获得更高的 FEC 额度；比例降低时发送端可先减少冗余，编码目标在预算更新成功后提高。复用现有帧时间戳环保存提交时的额度，因此 NVENC、AMF 和 FFmpeg 的延迟输出不会将旧帧套上新额度。编码器拒绝更新时保留已生效预算并限制重试频率；同时到来的手动或 ABR 请求不会被旧更新覆盖。反馈过期后请求回退比例，实际提高保护仍需经过下一预算窗口和编码器更新。

原生 NVENC、AMF 使用驱动的重配置结果。FFmpeg 只放行具有运行时码率更新路径的 libx264、QSV、NVENC；其他后端保留已生效的编码目标和 FEC 额度，不能把写入 `AVCodecContext` 字段当作更新成功。实际码率响应还受编码器的码率控制模式和驱动实现影响，需要对应硬件验收。

这里管理名义预算，不提供逐秒或逐包的硬流量上限。最低冗余、分片取整、填充、协议开销和编码器瞬时峰值仍会影响实际发送量。本实现不承担拥塞控制或链路容量发现。测试应固定总预算、编码器和网络条件，同时观察编码目标、FEC 比例、实际流量和恢复收益。

## 协议边界

主机 DESCRIBE 广告 `x-ss-video[0].fecControlVersion:1`。客户端仅在版本匹配且为旧 RS 视频格式时提交 `x-ml-video.fecSummaryVersion:1` 和 `x-ml-video.fecPercentage`。

- `0x5510`：客户端 FEC 汇总，三个大端 uint32：序号、数据分片数、缺失数据分片数。

汇总使用普通非可靠控制消息，每条仅结算自身窗口；丢失报告不扩大下一条分母。序号用于拒绝重复和倒退，并允许 uint32 回绕。无效数量、旧报告及错误长度被拒绝。消息归属复用现有控制连接和认证，不引入新的控制租约。

## 验证

复用主机 FEC 测试文件覆盖客户端固定优先、会话隔离、自动选择和上限、失效反馈回退、无效/重复/倒退/回绕报告，以及 RS 分块、最低冗余和线上的百分比一致性。预算回归覆盖 0–255%、整数边界、固定 0%、主机上限、启动与动态预留一致、窗口与滞回、更新拒绝、并发请求和重建时的已生效预算。复用既有码率换算测试和公共库回归；不保留原方案的大型回放样本或 SDK 测试入口。

构建验收包括核心单测、公共库 Debug/Release 回归、主机完整 Windows 编译与原生测试、PC 多平台构建，以及 Android lint、单测和 Release 编译。实机验收还需要旧客户端与旧主机组合、基础流畅性及相同码率下的恢复收益；构建通过不能替代这些结果。旧体验包的通过记录不用于声明本次收敛通过。
