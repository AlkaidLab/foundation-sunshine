# Privacy data inventory: what each client sends and what the server keeps

This list answers three questions: what is sent, why it is needed and how personal details are removed. Every entry names the code (`file:line`); the code locations are found by `scripts/telemetry/build_inventory.py` when the page is generated, so they follow the code.

## In one paragraph

Two independent switches (error reports, usage statistics), on by default; when one is off, nothing of that kind is sent. The data goes only to the developers' own server, `api.alkaidlab.com` (a Cloudflare Worker), not through an advertising network, and is not sold. Apart from feedback a person writes by hand and the log excerpt after a serious stream problem (only while error reports are on, cleaned text, see Never sent) there is no free text anywhere: names, paths, addresses and accounts are not in the payload to begin with.

The server does not store IP addresses, only the country code Cloudflare supplies; Workers Logs are off `worker:wrangler.toml:12`. The connection itself necessarily crosses the network and Cloudflare, as the network provider, sees the connecting address at the transport layer; that layer is not ours, and our code does not read, store or log it.

## Never sent

- Screen content, audio, keystrokes, files, clipboard content.
- The name of the computer, the Windows or macOS account, a device or a client; the name of a game or an application (a game is at most one of nine catalogue words).
- File paths, IP addresses, MAC addresses, ports, pairing identifiers, Steam, miHoYo or other account ids, Mirror酱 CDKs, passwords, tokens, cookies.
- Free text, with two exceptions. `user_report.message` is sent when the person presses Send, after the form showed it. And, only while error reports are on, the log excerpt after a serious stream problem (`stream_anomaly`, `log true`) is sent: the last two minutes of the host's own log, with text between quotes, brackets and braces dropped (a short bracket that only holds a code, such as `[E12]`, stays) and names, folders, addresses, e-mail addresses and keys cleaned; it stays text, not a fixed list of words.

## How it is enforced

- The sender has an allow-list: an event name or a property that is not listed is dropped before it leaves the computer `src/telemetry/events.cpp:431` (unit tests in `tests/unit/test_telemetry.cpp`).
- The Worker checks the same list again; a property of the wrong shape is dropped, never "cleaned and kept" `worker:src/schema.ts:94`.
