# Live MAT regressions and optional acceptance

Routine CI uses existing tests; it does not start a native capture or a full
streaming session:

- Windows CTest includes `mat_live_host_tests` for sender/source lifecycle and
  `mat_live_crypto_tests`, reusing the dependency's authentication/tamper cases.
- The independent `MAT software regressions` job runs six own-process CTests
  from `tools/sonic-mat-live`, plus operator package/identity/deployment checks.
- Existing RTSP lease and Web UI tests cover the lease expiry and status UI.

Run the same callback/IPC/pipe checks locally:

```powershell
./tools/sonic-mat-live/build.ps1 -Output ./build/mat-smoke-new -TestsOnly
./tools/sonic-mat-live/test-manage-live.ps1 -Output ./build/mat-operator-new
ctest --test-dir <host-build> -R '^mat_live_(host|crypto)_tests$' --output-on-failure
```

## Extended software integration (manual)

Run from the Sunshine root with MinGW GCC/CMake/Ninja/OpenSSL, Visual Studio C++
tools, Windows SDK and Python with `cryptography` available:

```powershell
./tests/mat-live/verify.ps1 -Output ./build/mat-live-new -Python <python-path>
```

The optional verifier builds the capture helpers and mock clients and runs:

- common-c CTest and an independent HKDF/AES-GCM packet oracle;
- controlled production RTSP negotiation: live7/Opus0, retired codec4/5 rejection,
  malformed capabilities and stale/duplicate acknowledgements;
- real AudioStream UDP receive/decoder threads: valid authenticated END succeeds;
  missing END or final data times out without a successful completion callback;
- two 1300-cycle UDP/FEC cases across RTP16 wrap, with 391 deliberate losses
  recovered; no hardware sink;
- host source/format/clock/identity/lease failures, cancellation and new sessions;
- actual private publisher/reader pipe tail, bounded acknowledgement and teardown;
- own-process object callbacks, paired lifecycle, generated IPC with a FAKE
  native worker, and explicit operator state/process-ownership regressions.

The paired hook tests also run eight callback threads for 1300 rounds with one
object domain and seven empty domains, concurrent reads, queue wrap and empty
domain reset/destroy. They check exact pre-submit PCM/XYZ/gain, independent sample
clocks and EOS, and reject missing objects in the selected domain. Separate cases
cover unfinished queue tickets, same-encoder overlap and per-domain QPC reversal.

All media bytes are generated by tests. No sample files, phone APK/JNI, finite
replay, disk-publication policy or native attachment is part of this suite.
The short `proof.json` summary and per-suite logs report software behavior only,
not native encoding or Atmos output. No recursive source/artifact hash inventory
is collected. The capture build retains its three required runtime trust hashes.

## Full RTSP/video and native acceptance (manual)

`live_verify.py --preflight-only` uses a normally built Sunshine with isolated
certificates, config and ports, checks pairing/start/stop, and never attaches a
native source. Pass explicit `--host-build` and `--client-build` directories.
`--ui-preflight` additionally checks the MAT switch, retirement of manual source
parameters and read-only status polling against a pending exclusive auto pipe.
No publisher is started.
`--ticket-preflight` instead holds two overlapping incomplete RTSP connections
past the original launch deadline, then checks asynchronous expiry after the last
claim closes. It disables audio and never sends ANNOUNCE/PLAY; no media starts.
`host_support.py` owns only test certificates, a read-only prerequisite check and
orderly shutdown of the test's own host.
`preflight_exit_test.py --output <fresh-dir> --host-build <host-dir>
--client-build <mock-client-dir>` checks successful preflight, cleanup-failure
exit codes and preservation of a primary exception using isolated hosts only.

`build-client.ps1` builds a fileless strict-live mock client and generated H.264
encoder/decoder self-test with explicitly supplied encoder/decoder FFmpeg builds.
The client decodes video in memory and consumes MAT callbacks without a device.
The full `live_verify.py` native mode additionally requires explicit source,
engine, component, endpoint and hash arguments and current operator authorization.
Its publisher must use the trusted Program Files deployment used by `manage-live.ps1`;
an executable started directly from a build directory is not an automatic host source.
It is not invoked by the software verifier.
Add `--bed-7.1.4` to this authorized native mode to generate 12 distinct static
channels and two moving objects, require the complete input mask and verify
14 inputs per accepted source round. The software IPC tests exercise this layout
and dynamic-only input separately; neither mock playback nor a successful encode
proves a hardware sink's Atmos decoding or speaker output.

The historical finite, Android and recorder harnesses are available only on
[the archive branch](https://github.com/AlkaidLab/foundation-sunshine/tree/codex/mat-history-20261023).
