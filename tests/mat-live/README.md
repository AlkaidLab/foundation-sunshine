# Live MAT regressions and optional acceptance

Routine CI uses existing tests; it does not start a native capture or a full
streaming session:

- Windows CTest includes `mat_live_host_tests` for sender/source lifecycle and
  `mat_live_crypto_tests`, reusing the dependency's authentication/tamper cases.
- `mat_mock_output_tests` connects the real authenticated receiver to a bounded
  output queue and simulated device. It covers short/zero writes, write failures,
  slow/stalled consumption, route/capability loss, fresh-session reconnect and EOS
  drain. A virtual clock drives 500 cycles with arrival jitter; accepted, written
  and consumed bytes must have identical SHA256. No MAT decoder is simulated.
- The independent `MAT software regressions` job runs six own-process CTests
  from `tools/sonic-mat-live`, plus operator package/identity/deployment checks.
- Existing RTSP lease and Web UI tests cover the lease expiry and status UI.

Run the same callback/IPC/pipe checks locally:

```powershell
./tools/sonic-mat-live/build.ps1 -Output ./build/mat-smoke-new -TestsOnly
./tools/sonic-mat-live/test-manage-live.ps1 -Output ./build/mat-operator-new
ctest --test-dir <host-build> -R '^mat_(live_(host|crypto)|mock_output)_tests$' --output-on-failure
```

## Extended software integration (manual)

Run from the Sunshine root with MinGW GCC/CMake/Ninja/OpenSSL, Visual Studio C++
tools, Windows SDK and Python with `cryptography` available:

```powershell
./tests/mat-live/verify.ps1 -Output ./build/mat-live-new -Python <python-path>
```

The optional verifier builds the capture helpers and mock clients and runs:

- common-c CTest and an independent HKDF/AES-GCM packet oracle;
- controlled production RTSP negotiation: live7/Opus0, retired codec4/5 rejection,
  malformed capabilities and stale/duplicate acknowledgements;
- real AudioStream UDP receive/decoder threads: valid authenticated END succeeds;
  missing END/tail, stalled output, route loss and cancellation while draining
  fail without a successful completion callback;
- two 1300-cycle UDP/FEC cases across RTP16 wrap, with 391 deliberate losses
  recovered; no hardware sink;
- the same mock-output scenarios through real UDP/RTP/FEC, including 1300 paced
  virtual cycles and source/written/consumed SHA equality after loss recovery;
- controlled device capabilities through the real RTSP client: AUTO selects Opus
  for unavailable/unsupported output, strict MAT rejects it before connecting;
- host source/format/clock/identity/lease failures, cancellation and new sessions;
- actual private publisher/reader pipe tail, bounded acknowledgement and teardown;
- own-process object callbacks, paired lifecycle, generated IPC with a FAKE
  native worker, and explicit operator state/process-ownership regressions.

The paired hook tests also run eight callback threads for 1300 rounds with one
object domain and seven empty domains, concurrent reads, queue wrap and empty
domain reset/destroy. They check exact pre-submit PCM/XYZ/gain, independent sample
clocks and EOS, and reject missing objects in the selected domain. Separate cases
cover unfinished queue tickets, same-encoder overlap and per-domain QPC reversal.

All media bytes are generated by tests. No sample files, phone APK/JNI, finite
replay, disk-publication policy or native attachment is part of this suite.
The short `proof.json` summary and per-suite logs report software behavior only,
not native encoding or Atmos output. No recursive source/artifact hash inventory
is collected. The capture build retains its three required runtime trust hashes.

## Full RTSP/video and native acceptance (manual)

`live_verify.py --preflight-only` uses a normally built Sunshine with isolated
certificates, config and ports, checks pairing/start/stop, and never attaches a
native source. Pass explicit `--host-build` and `--client-build` directories.
`--ui-preflight` additionally checks the MAT switch, retirement of manual source
parameters and read-only status polling against a pending exclusive auto pipe.
No publisher is started.
`--ticket-preflight` instead holds two overlapping incomplete RTSP connections
past the original launch deadline, then checks asynchronous expiry after the last
claim closes. It disables audio and never sends ANNOUNCE/PLAY; no media starts.
`host_support.py` owns only test certificates, a read-only prerequisite check and
orderly shutdown of the test's own host.
`preflight_exit_test.py --output <fresh-dir> --host-build <host-dir>
--client-build <mock-client-dir>` checks successful preflight, cleanup-failure
exit codes and preservation of a primary exception using isolated hosts only.

`build-client.ps1` builds a fileless strict-live mock client and generated H.264
encoder/decoder self-test with explicitly supplied encoder/decoder FFmpeg builds.
The client decodes video in memory and feeds MAT callbacks to the same mock
output. Its completion requires both authenticated END and simulated sink drain;
the result records written/consumed SHA, playback frames and peak backlog.
The END callback returns success only after the bounded drain completes.
The threaded audio watchdog client uses this output too. A mock capability is
test input, never proof of an Android route or permission to play MAT as PCM.
The full `live_verify.py` native mode additionally requires explicit source,
engine, component, endpoint and hash arguments and current operator authorization.
Its publisher must use the trusted Program Files deployment used by `manage-live.ps1`;
an executable started directly from a build directory is not an automatic host source.
It is not invoked by the software verifier.
Add `--bed-7.1.4` to this authorized native mode to generate 12 distinct static
channels and two moving objects, require the complete input mask and verify
14 inputs per accepted source round. The software IPC tests exercise this layout
and dynamic-only input separately; neither mock playback nor a successful encode
proves a hardware sink's Atmos decoding or speaker output.

The historical finite, Android and recorder harnesses are available only on
[the archive branch](https://github.com/AlkaidLab/foundation-sunshine/tree/codex/mat-history-20261023).

## Android/JNI mock acceptance (manual)

`android/verify.py` builds a small instrumented APK with the current common-c
receiver; it does not build or modify the archived Android client. Supply an
Android OpenSSL build containing `include/` and `x86_64/libcrypto.a`:

```powershell
python tests/mat-live/android/verify.py --sdk <SDK> --ndk <NDK> --openssl <Android-OpenSSL> --java-home <JDK> --output <fresh-dir> --serial emulator-5560
```

Start an x86_64 emulator first. The runner requires SDK platform 34 and SDK CMake
3.22.1; it installs only on the explicitly selected emulator, enables CheckJNI
for the diagnostic process, then restores the setting and removes its APK.
No Gradle dependencies are downloaded. Run this manually, outside routine CI.

Ten cases cover native-thread callbacks, copying borrowed buffers before native
reuse, bounded Java mock writes/drain and SHA equality, authentication failure,
missing END, sink failure, cancellation at END, preservation of a Java callback
exception, stale epochs, callback rejection and two fresh-session reconnects.
The added RTP/FEC case reuses the existing loopback transport adapter and recovers
one deliberately absent data shard using only three data shards plus one parity
shard, then compares the generated and consumed SHA. Native code is built as
RelWithDebInfo so common-c's Debug-only extra-shard FEC validation is excluded;
the debuggable APK still runs with CheckJNI enabled.
Each successful session consumes 128 generated cycles. The END callback returns
success only after mock drain; redundant authenticated END packets notify Java once.
The default `proof.json`, instrumentation and CheckJNI logs report the generated
JNI cases only. The source is generated in memory, not captured or replayed media.
For the JNI lifetime/thread rules see
[Android JNI tips](https://developer.android.com/ndk/guides/jni-tips).

The JNI builder defaults to emulator-only installation. An explicitly selected
physical device requires `verify.py --allow-physical-device` and an explicit
serial; supported ABIs are x86_64 and arm64-v8a, selected from that device.
Output remains mock. The full-session process adapter also accepts explicit
physical-device opt-in from a separate LAN test harness; the normal isolated
runner below retains its emulator address and default emulator-only guard.

The same APK also contains a full common-c `LiStartConnection` adapter and an
Android MediaCodec H.264 decoder in ByteBuffer mode. Run against an isolated,
normally built Sunshine with no native capture:

```powershell
python tests/mat-live/live_verify.py --output <fresh-dir> --host-build <Sunshine-build> --adb <adb.exe> --android-serial emulator-5560 --android-apk <diagnostic.apk> --android-session-only --seconds 8 --port 52410
```

This checks real encrypted RTSP/control, video RTP/FEC, Android decode and orderly
teardown. With no armed MAT source, AUTO6 must negotiate Opus0. The isolated launch
uses the existing `continuousAudio` option to send idle Opus silence, which the
compressed-audio mock discards. It keeps host playback enabled to avoid selecting
a virtual sink. This result is not a live-MAT or source-audio integrity result.

For authorized native MAT acceptance, omit `--android-session-only` and supply the
existing explicit native source/operator arguments as well as the three Android
arguments. The APK is prepared before native attachment; strict live7 uses actual
AudioStream authentication/reassembly and JNI callbacks into the same bounded
Java mock. Acceptance requires publisher/received/consumed SHA equality,
authenticated EOS after mock drain, concurrent video decode and verified hook
restoration. This mode still needs fresh native-capture authorization.

The historical Android application stays untouched. This diagnostic APK contains
no AudioTrack, HDMI output, Dolby decoder or acoustic synchronization test.


Emulator-specific paced UDP probes and network fault isolation are maintained
separately from this host PR. They are not required by the APK, mock session,
normal build or CI.
